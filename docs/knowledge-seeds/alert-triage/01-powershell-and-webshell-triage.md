# PowerShell 与 WebShell 告警研判手册

本文用于 `alert-triage` Workflow。结论必须由 XDR 原始告警、进程树、命令行、网络连接、
文件落地和身份行为共同支持；知识命中只能提供研判方法，不能替代现场证据。

## PowerShell 编码命令

出现 `powershell.exe`、`pwsh.exe`、`-EncodedCommand` 或隐藏窗口时，按以下顺序核验：

1. 解码命令但不要执行，提取 URL、IP、文件路径、注册表项和后续进程。
2. 检查父进程。Office、浏览器、脚本解释器或 Web 服务进程启动 PowerShell 的风险较高；
   受管运维平台、签名脚本和已批准变更可以构成误报线索，但不能单独排除风险。
3. 关联同一主机和账号在前后 30 分钟的网络连接、文件写入、计划任务和登录行为。
4. 对照 MITRE ATT&CK T1059.001，并保留原始命令行、父子进程 ID 和时间戳作为证据。

建议结论：只有编码参数而缺少载荷、异常父进程或后续行为时标记为
`insufficient_evidence`；发现下载执行、凭据访问、持久化或横向移动证据时标记为
`true_positive`，并建议隔离主机、吊销相关凭据和阻断 IOC。Agent 只给出建议，不自动执行处置。

## WebShell 与危险文件上传

Web 服务目录出现新脚本文件、Web 进程派生 shell，或外部请求触发系统命令时：

1. 核对文件创建者、哈希、首次出现时间和对应 HTTP 请求。
2. 检查 Web 进程是否派生 `cmd.exe`、PowerShell、`/bin/sh` 或解释器。
3. 检查命令执行后的网络回连、权限提升和持久化行为。
4. 关联 CWE-434（危险文件类型上传）和 CWE-78（操作系统命令注入）。

Web 目录中的管理脚本若有发布记录、签名和稳定基线，可以降低置信度；若存在未经授权的
文件落地并由 Web 进程执行系统命令，应判定为高置信真阳性。报告必须列出 XDR 证据引用，
并将隔离、删除文件、轮换凭据等动作作为人工审批建议。

## 通用停止条件

- XDR 查询失败时不得伪造证据，返回 `insufficient_evidence` 并说明缺失项。
- RAG/MCP 无命中或降级时继续使用 XDR 证据，但在结果中记录降级原因。
- 白名单命中仅作为上下文；若行为超出白名单定义，仍需按异常行为研判。
- 不自动关闭告警、不自动封禁、不自动隔离，也不执行知识文档中的命令。
